# Free launch on Render + Neon + Resend (no card)

One free Render web service runs both the member web app (public, at
`app.hellosandar.com`) and the API (private, inside the same container). Neon
hosts Postgres, Resend sends account email from `noreply@hellosandar.com`.

Trade-off of the free plan: after 15 minutes without visitors the service
sleeps, and the next visitor waits about 30–60 seconds while it wakes.

For the Google Cloud setup (needs billing) see `deploy-production.md`. The
"Before you start" checklist there applies here too.

## 1. Accounts (you)

1. **Neon** (neon.tech): create project `sandar`. Launch uses *AWS US East
   (Ohio)*; keep the Render service in the same region (`render.yaml`). Copy the **pooled** connection string (ends in
   `?sslmode=require`).
2. **Resend** (resend.com): Domains → Add `hellosandar.com`. Add the DNS
   records it shows (SPF/DKIM, usually 3) in Cloudflare, then wait for
   "Verified". API Keys → create one with *Sending access* only.
3. **GitHub**: Render deploys from a GitHub repository, so Sandar-App needs a
   private repo (e.g. `sandarapp/sandar-app`).
4. **Render** (render.com): sign up with GitHub and allow access to that repo.

## 2. Database (from your laptop)

```bash
export DATABASE_URL='<neon pooled connection string>'
npm run db:migrate:prod
POLICY_VERSION=2026-11-launch node_modules/.bin/tsx scripts/setup-official-spaces.ts
# Only after you have decided the policy text is ready to go live:
SITE_URL=https://hellosandar.com POLICY_VERSION=2026-11-launch npm run policies:setup -- --legal-approved
unset DATABASE_URL
```
Registration stays closed until the policies step has run.

## 3. Create the service

Render → New → **Blueprint** → pick the Sandar-App repo. It reads
`render.yaml` and asks for three values:

| Key | Value |
| --- | --- |
| `DATABASE_URL` | Neon pooled connection string |
| `RESEND_API_KEY` | the Resend key |
| `DATA_ENCRYPTION_KEY` | output of `openssl rand -hex 32` (keep a copy in your password manager) |

`BFF_SHARED_SECRET` is generated by Render. The first build takes several
minutes.

## 4. Domain

Render → service `sandar` → Settings → Custom Domains → add
`app.hellosandar.com`. In Cloudflare add the CNAME Render shows, set to
**DNS only** (grey cloud). Render issues the certificate.

## 5. Check the visitor IP

Rate limits must see each visitor's own address. In Render → Shell, or from
the logs of a login attempt, confirm which header carries it. If the
`X-Forwarded-For` value's last entry is Render's proxy rather than the
visitor, set `VISITOR_IP_HEADER` to the header Render's edge sets (for
example `cf-connecting-ip` or `true-client-ip`) and redeploy.

## 6. Smoke test

Same list as `deploy-production.md` §9, on `https://app.hellosandar.com`.
Then set `NEXT_PUBLIC_MEMBER_APP_URL=https://app.hellosandar.com` for the
website in Cloudflare and deploy the website.

## Limits to know

- Free Render: 512 MB RAM (Sandar uses about 220 MB), 750 instance hours a
  month (enough for one always-sleeping-when-idle service).
- Free Neon: 0.5 GB storage, short restore window. Take a weekly `pg_dump`.
- Free Resend: 3,000 emails a month, 100 a day.
